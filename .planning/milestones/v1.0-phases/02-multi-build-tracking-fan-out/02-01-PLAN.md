## Phase Goal

**As a** developer with several GitHub Actions workflows in flight, **I want to** hear every meaningful per-build status change identified by its run title, **so that** a non-top-row failure or completion is never silently missed.

<objective>
Prove the production-quality end-to-end multi-build path: all-row scrape → normalized snapshots → per-id Map transitions → one immediate announcement per changed suite.

Purpose: Establish the architecture that satisfies MULTI-01 through MULTI-04 while implementing D-02, D-04, D-08, and D-09 without crossing the Phase 3 module/speech boundary.
Output: `buildStates`, `InFlightBuildStore`, and an ordered fan-out poll path in `index.js`, with two-suite Jest fixtures proving the complete path.
</objective>

<interfaces>
Existing contracts to preserve:
- `Status`: frozen enum containing queued, running, success, failure, cancelled, skipped, action_required, unknown.
- `normalizeStatus(ariaLabel) -> Status`: normalize at the scrape boundary.
- `BuildState(buildName, status, gitLog)`: `buildName` is the check-suite DOM id; `gitLog` is display identity.
- `BuildState.diffToSentence(previousState, dictionary) -> string` and `BuildState.colorCode() -> string|undefined`.
- `say(statement, colorCode)`: existing stderr plus shell-backed macOS speech boundary; its implementation is unchanged in Phase 2.

Contracts created by this plan:
- `buildStates(url) -> Promise<BuildState[]|null>`: ordered valid rows or null for an unusable scrape.
- `InFlightBuildStore() -> { apply(states), has(id), get(id), size }`: private Map-backed lifecycle state and test inspection.
- `apply(BuildState[]) -> Array<{ statement, colorCode }>`: ordered announcement descriptors.
- `actionSoundJob(url?, announce?, store?) -> Promise<Array<{ statement, colorCode }>>`: poll coordinator with defaults for the live CLI and injectable seams for Jest.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions HTML → buildStates | Untrusted DOM ids, aria labels, and titles enter the process |
| BuildState[] → InFlightBuildStore | Untrusted display titles must not become lifecycle identity |
| Announcement descriptor → say | Scraped title reaches the inherited shell-backed speech path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | InFlightBuildStore identity | high | mitigate | Key the private Map exclusively by check-suite DOM id; tests use colliding titles with distinct ids |
| T-02-02 | Tampering / Denial of Service | buildStates failure/partial DOM | high | mitigate | Null scrape is a poll no-op; malformed rows are isolated; no absence-driven deletion |
| T-02-03 | Elevation of Privilege | inherited `say` via shell string | high | transfer | SAFE-01 is locked to Phase 3; preserve the existing `say(statement,colorCode)` implementation and add no new shell interpolation or invocation path |
| T-02-04 | Repudiation | concurrent announcement order | medium | mitigate | Preserve DOM order in snapshots, descriptors, and synchronous callback invocation; assert exact call order |
| T-02-SC | Tampering | package supply chain | low | accept | No package install or dependency change occurs in this phase |
</threat_model>
